# `arkos sandbox` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `arkos sandbox` runs a second, separate Arkos (its own config, daemon and sessions) to try a theme or effect in, aims any `arkos` command at it, and never changes the user's own setup.

**Architecture:** A new env var `ARKOS_CONFIG_DIR` joins `ARKOS_APP_SUPPORT` so the sandbox moves only Arkos's folders; `ARKOS_SANDBOX=1` marks the instance and gates every write outside the sandbox (Claude Code colours, hooks and skill, login item, update poll). A new `sandbox.rs` builds the environment, copies the user's config on first start, and dispatches: a folder opens a window, a command word re-runs this executable with the sandbox environment, and `status`, `stop`, `reset` are its own, all behind a `Host` trait so the logic is tested without processes.

**Tech Stack:** Rust; `std::process::Command` with `pre_exec(setsid)` as `launch.rs`; the existing `telemetry::channel()`, `open_cli::panes_cli_to` and `agent_cli::customize`.

**Spec:** `docs/superpowers/specs/2026-10-29-sandbox-design.md`

## Global Constraints

- The sandbox environment sets exactly `ARKOS_CONFIG_DIR`, `ARKOS_APP_SUPPORT`, `ARKOS_SANDBOX=1`, `ARKOS_TELEMETRY=off`, and removes `ARKOS_SESSION_ID`, `ARKOS_RELAUNCH` and every variable starting with `CLAUDE` except `CLAUDE_CODE_OAUTH_TOKEN`.

## Review Focus

1. `arkos sandbox` run from inside a sandbox shell (the variables already set): it must open a window of the same sandbox, not nest a third instance (Task 2: the dirs come from `home` and the channel, never from the current `ARKOS_CONFIG_DIR`).
2. `reset` while a window is still up: refused, never a deletion under a running daemon (Task 2 tests both the running and the stopped case).
3. A user with no `~/.config/arkos` at all: first start makes the sandbox folders and the window starts with defaults, no error (Task 2).
4. `arkos sandbox hooks install` from a dev build: refused with `not in a sandbox`, or the user's hooks would point at a debug binary (Task 3).
5. `ARKOS_CONFIG_DIR` set to an empty string: treated as unset, as the other variables are (Task 1).

pub struct Dirs { pub root: PathBuf, pub config: PathBuf, pub state: PathBuf }
pub fn dirs(home: &Path, channel: &telemetry::Channel) -> Dirs;              // arkos-sandbox or arkos-sandbox-dev
pub struct SandboxEnv { pub set: Vec<(String, String)>, pub remove: Vec<String> }
pub fn env(dirs: &Dirs, current: &[(String, String)]) -> SandboxEnv;         // `remove` lists the names present in `current` that match the rule
pub fn apply(cmd: &mut std::process::Command, env: &SandboxEnv);
pub fn first_start(dirs: &Dirs, real_config: &Path) -> std::io::Result<bool>; // true when it copied
pub const COMMANDS: &[&str] = &["open", "video", "panes", "theme", "effect", "settings", "config", "guide", "doctor", "telemetry", "hooks", "notify"];
pub trait Host {
    fn run(&mut self, exe: &Path, args: &[String], env: &SandboxEnv) -> i32;
    fn spawn_window(&mut self, exe: &Path, folder: &Path, env: &SandboxEnv, log: &Path) -> std::io::Result<u32>;
    fn windows(&mut self, exe: &Path, env: &SandboxEnv) -> Result<Vec<(u32, PathBuf)>, String>; // panes --all --json; Err when the daemon does not answer

    fn current_vars(&self) -> Vec<(String, String)>;

pub struct Ctx<'a> { pub home: &'a Path, pub channel: telemetry::Channel, pub exe: &'a Path, pub real_config: &'a Path, pub cwd: &'a Path }
