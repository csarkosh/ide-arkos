# Web Pane (WKWebView) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser tab is a `WKWebView` drawn inside the Arkos window, under a 28 px bar of Arkos's own (back, forward, reload, address, progress, open outside); Chrome docking and everything it needed (the Accessibility API, the probe, the dock and undock commands, app mode, the drag-in) are removed; `arkos open <url | file.html>` opens a web tab from a session, reusing and reloading a tab already on that address; a local page follows its file.

**Architecture:** `web.rs` holds the pure rules (`parse_address`, `read_access_root`, the title rule, the zoom ladder, the `Web` trait with `FakeWeb`) and the `WebModel` state machine; `wk_web_view.rs` is the one AppKit file (the `WKWebView` child of the window's content view, the navigation and UI delegates as one `define_class!` each, the per-frame placement); `web_view.rs` is the gpui entity (`WebView`, the video tab's `VideoView` as the template: polling, follow rule, animation frames while loading); `web_element.rs` draws the bar and the blank and failed screens; `screen.rs` keeps the `NSWindow` helpers that `ax.rs` had. `Tab::Browser { url: String }` is the model. The targeted channel gains `OpenKind::Web`.

**Tech Stack:** Rust 2021, gpui 0.2.2 (unchanged), `objc2-web-kit` 0.3.2 (new, default features off: `WKWebView`, `WKWebViewConfiguration`, `WKPreferences`, `WKWebpagePreferences`, `WKNavigation`, `WKNavigationDelegate`, `WKUIDelegate`, `WKWebsiteDataStore`, `WKProcessPool`, `WKNavigationAction`, `WKNavigationResponse`, `WKFrameInfo`, `WKWindowFeatures`, `WKBackForwardList`, `WKUserContentController`, `WKError`, plus the ones the compiler asks for), the `objc2-app-kit` and `objc2-foundation` already in the tree.

**Spec:** `docs/superpowers/specs/2026-10-24-web-pane-design.md`.

## Global Constraints

- Machine rules: every cargo call is `nice -n 15 ~/.cargo/bin/cargo ...`; the worktree's `.cargo/config.toml` (`jobs = 3`, shared `target-dir`) stays; no `--release` on the laptop; never two cargo processes at once; focused filters while iterating, the workspace suite once per task; the warning check is `cargo check --workspace --all-targets`.
- One new dependency, `objc2-web-kit`; no gpui bump; no `wry`.
- WebKit is called only on the UI thread. No gpui call from inside a WebKit delegate callback: a delegate writes a `Signal` into a cell the next poll reads.
- Colours from `root.theme` at paint time; the one push into WebKit (`underPageBackgroundColor`) from `Root::finish_theme`.
- No em-dashes. Warning-free. Headless tests only; nothing in `cargo test` constructs a `WKWebView`.
- Every removal of section 9 of the spec is done in Task 2, so Tasks 3 onward build on a tree with no Chrome docking left.

## Review Focus

1. The web view is never visible when it should not be: an overlay opens over a web tab (palette, prompt, menu, drag overlay), the tab is switched away, the pane is hidden by a maximized sibling, the window is minimized. `Root::covered` is one function and every overlay is in it (Task 3's `every_overlay_covers_the_page`).
2. A saved workspace from 0.6 with `{"Browser":{"url":null,"app_mode":true}}` opens as a blank web tab, and one with a URL opens it (Task 2's `a_0_6_browser_tab_reads_as_a_web_tab`).
3. A failed `localhost` load shows the reason and Retry, and a retry after the server starts shows the page; a cancelled navigation is not a failure (Task 3's model tests).
4. `arkos open` on an address already shown reuses and reloads that tab, and `--at` with a web target is refused before anything is sent (Task 5).
5. A 0.6 config with `[browser] app_mode = true` or a keybinding for `dock a chrome window` still loads, with a notice for the binding (Task 2).

## Rulings taken while planning

1. The `WKWebView` is a sibling of gpui's own view under the window's content view (gpui adds its view as a subview of `contentView`, `platform/mac/window.rs`), added after it so it draws above; not a subview of gpui's view, whose layer gpui owns. Key equivalents reach gpui's view first because the content view asks its subviews in order and gpui's `performKeyEquivalent:` override answers what the keymap binds; the probe (Task 1) confirms.
2. The content view is not flipped (AppKit's default); the probe reads `isFlipped` once and the arithmetic takes the flag rather than assuming.
3. The `WebView` entity is created on first draw and lives in `Root.webs`, dropped in `close_tab`; the `WkWebView`'s `Drop` removes the view from its superview.
4. Polling, not KVO: `isLoading`, `estimatedProgress`, `URL`, `title`, `canGoBack`, `canGoForward` are read each frame the tab is visible (six message sends; nothing while hidden) and once a second while hidden for the title. The delegates carry only what polling cannot see: the failures, the commit, the process termination, new-window requests and undisplayable responses.
5. Retired keybinding names (`dock a chrome window`, `undock chrome window`, `new single-page browser tab`) are a `RETIRED` list in `keymap.rs`: `validate` reports them as a notice line, "no longer a command, ignored", not as an error, and `bindings_for` skips them.
6. `PROTOCOL_VERSION` 9; `WEB_OPEN_FROM` 9; the daemon's `direct_target` takes the action and refuses a `Web` open to an older window.
